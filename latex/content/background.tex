\subsection{GGM trees}
\paragraph{Pseudorandom functions.}
A central problem in cryptography is generating randomness that appears truly 
random while remaining reproducible from a secret key. A 
\textbf{pseudorandom function} (PRF) addresses this problem: it is a keyed function 
that, to any efficient adversary without the key, is indistinguishable from a truly 
random function. Intuitively, a PRF expands a short secret key into an exponentially 
large table of ``random-looking'' outputs without storing the table explicitly.

PRFs are fundamental primitives in symmetric cryptography and appear in the 
construction of message authentication codes (MACs), stream ciphers, and 
key-derivation functions. 
%For example, \textsc{AES} in counter mode defines a 
%PRF: given a secret key~$k$ and an index~$i$, the output $\mathrm{AES}_k(i)$ is 
%computationally indistinguishable from a uniformly random string.
A standard construction of PRFs from one-way functions is the 
\textbf{Goldreich--Goldwasser--Micali (GGM) tree}~\cite{GGM86}, which builds a 
PRF by iteratively applying a pseudorandom generator along the branches of a 
binary tree indexed by the input bits. GGM trees are the main PRF construction 
studied in this work.


\begin{definition}[GGM Tree]
\label{def:ggm}
Let $\PRG : \{0,1\}^{\lam} \to \{0,1\}^{2\lam}$ be a length-doubling pseudorandom
generator, decomposed as $\PRG(x) = (\PRGl(x),\, \PRGr(x))$, where $\PRGl$ and
$\PRGr$ each output $\lam$ bits.  Given a root seed
$\seed_r \in \{0,1\}^{\lam}$ and a depth $d$, the \emph{GGM tree} is a complete
binary tree of depth $d$ in which:
\begin{itemize}
  \item the root holds $\seed_r$;
  \item each internal node $v$ storing seed $s$ generates its left child as
        $\PRGl(s)$ and its right child as $\PRGr(s)$;
  \item the $2^{d}$ leaves are the \PRG\ outputs at depth $d$.
\end{itemize}
\end{definition}

The crucial property exploited by ZK signature schemes is the
\emph{punctured-PRF property}: given all leaf seeds \emph{except} leaf~$i$, it is
computationally infeasible to recover the seed at leaf~$i$, provided $\PRG$ is
a secure pseudorandom generator.  This makes the \GGM\ tree suitable for hiding
one or more seeds while revealing the rest, as shown in Figure~\ref{fig:ggm-receiver}.

\paragraph{Incomplete \GGM\ trees.}
When the number of required leaves $t$ is not a power of $2$, a scheme may use an
\emph{incomplete} tree: leaves appear at multiple levels, and internal nodes near
the bottom may have fewer than two children or act as leaves themselves. This
reduces memory and computation, but the additional index-tracking logic introduces
new fault surfaces. The scheme may also use the first $t$ leaves of the tree.

\subsection{Seed trees in Fiat--Shamir zero-knowledge signatures}
\label{sec:template}
% ============================================================

All schemes considered in this work follow the same skeleton, and it is worth
stating it once before instantiating it. A $3$- or $5$-pass identification
protocol is repeated $t$ times in parallel and made non-interactive by the
Fiat--Shamir transform. Round $i$ needs a fresh ephemeral secret, which the
signer derives from a leaf seed $\eseed_i$; the $t$ leaf seeds are the leaves
of a single \GGM\ tree grown from one root seed, so that the signer stores
$\lambda$ bits instead of $t\lambda$.

The Fiat--Shamir challenge $\mathbf{c}$ has fixed weight $w$ and splits the
rounds in two. For the $w$ \emph{hidden} rounds ($i \in \calH$) the signer
publishes a response $\resp_i$ that combines the ephemeral secret with the
long-term secret key; the leaf seed $\eseed_i$ must therefore stay secret,
since $\resp_i$ and $\eseed_i$ together determine the long-term secret. For
the $t-w$ \emph{revealed} rounds ($i \in \calR$) the signer publishes nothing
but the seed, and the verifier recomputes the round's commitment itself.

Publishing $t-w$ individual seeds would undo the compression, so the signer
instead publishes a small set of \emph{internal} nodes---the boundary of the
hidden subtree---from which the verifier can recompute exactly the revealed
leaves and no others. This set is what we call the \emph{path}, and computing
it is the only place in the signing algorithm where the code must decide, per
node, whether a seed may be released. That decision is the object of this
paper: every attack surveyed in Section~\ref{sec:relwork} and every attack we
mount in Section~\ref{sec:app} corrupts it, and the abstraction of
Section~\ref{sec:abstract} is built around it.

\subsection{The MEDS signature scheme}
\label{sec:meds}
% ============================================================

The Matrix Equivalence Digital Signature (MEDS) scheme~\cite{ChouNPRRST23} is
a code-based signature whose security rests on the hardness of the Matrix Code
Equivalence (MCE) problem. Because the practical attacks of
Section~\ref{sec:app} target the MEDS reference implementation, we describe it
in more detail than the other instances.

\paragraph{Matrix codes and the MCE problem.}
A \emph{matrix code} of dimension $k$ is a $k$-dimensional $\Fq$-subspace
$\Mat \subseteq \Fq^{m \times n}$. Two matrix codes $\Mat, \Matd$ are
\emph{equivalent} if there exist $A \in \GL_m(q)$ and $B \in \GL_n(q)$ with
\[
  \Matd \;=\; A\,\Mat\,B \;:=\; \{\, A\,C\,B \;:\; C \in \Mat \,\}.
\]

\begin{definition}[Matrix Code Equivalence]
\label{def:mce}
Given two $k$-dimensional matrix codes $\Mat, \Matd \subseteq \Fq^{m\times n}$,
the \emph{MCE problem} asks for a pair $(A,B) \in \GL_m(q) \times \GL_n(q)$
such that $\Matd = A\,\Mat\,B$.
\end{definition}

In implementations a matrix code is handled through a generator matrix
$G \in \Fq^{k \times mn}$ whose $k$ rows are the vectorisations
$\vect(C_1),\ldots,\vect(C_k)$ of a basis of $\Mat$. Write $\pimap{A}{B}$ for
the induced row-wise map
\[
  \pimap{A}{B}\bigl(\vect(C)\bigr) \;=\; \vect\bigl(A\,C\,B\bigr),
\]
extended to generator matrices by applying it to each row. Since a generator
matrix fixes a basis but equivalence only relates the underlying
\emph{subspaces}, the relation between two generator matrices of equivalent
codes carries a third, unknown ingredient: a change of basis
$T \in \GL_k(q)$. Concretely, $G_0$ and $G_1$ generate equivalent codes if and
only if there exists a triple $(A,B,T)$ with
\begin{equation}
  \label{eq:mce-gen}
  G_1 \;=\; T \cdot \pimap{A}{B}(G_0),
  \qquad\text{equivalently}\qquad
  G_1 \;=\; \SF\bigl(\pimap{A}{B}(G_0)\bigr),
\end{equation}
where $\SF$ denotes the systematic form, which absorbs $T$ by fixing a
canonical basis.

\begin{remark}[Why MCE is not linear algebra]
\label{rem:mce-hardness}
The unknown $T$ in~\eqref{eq:mce-gen} is the entire source of hardness, and it
is easy to miss. If one \emph{fixes} the basis correspondence, i.e.\ assumes
$T = I$ so that the $i$-th basis matrix $C^{(0)}_i$ of $\Mat$ maps to the
$i$-th basis matrix $C^{(1)}_i$ of $\Matd$, then the defining relations become
\[
  A^{-1} C^{(1)}_i \;=\; C^{(0)}_i B, \qquad i = 1,\ldots,k,
\]
which is a \emph{homogeneous linear} system in the joint unknowns
$(A^{-1}, B)$ and is solved by Gaussian elimination. This is not a weakness of
MCE but a routine used inside MEDS: key generation samples a random
$T_i \in \GL_k(q)$, forms $G'_0 = T_i G_0$, and recovers $(A_i, B_i^{-1})$ from
exactly this linear system (the $\Solve$ call of
Algorithm~\ref{alg:keygen_meds}), with the scalar constraint
$a_{m-1,m-1}$ pinning down the solution up to the residual scaling
$(A,B) \mapsto (\lambda A, \lambda^{-1} B)$. Publishing only
$\SF(\pimap{A_i}{B_i}(G_0))$ then destroys the basis correspondence, and with
it the linearity: with $T$ unknown, \eqref{eq:mce-gen} is a system of
\emph{bilinear} equations. MCE is Tensor-Isomorphism-complete in the sense of
Grochow and Qiao~\cite{GrochowQiao23}; see~\cite{ReijndersST23,NarayananQT24}
for the best known classical algorithms.
\end{remark}

\paragraph{Key generation.}
Key generation (Algorithm~\ref{alg:keygen_meds}, Appendix~\ref{app:algs})
derives a public seed $\sigma_{G_0}$, expands it into a systematic generator
matrix $G_0$, and then produces $s-1$ equivalent codes: for each $i$ it samples
$T_i \in \GL_k(q)$, forms $G'_0 = T_i G_0$, recovers $(A_i,B_i^{-1})$ by the
linear solve of Remark~\ref{rem:mce-hardness}, and sets
$G_i \leftarrow \SF(\pimap{A_i}{B_i}(G_0))$. The public key is
$(\sigma_{G_0}, G_1, \ldots, G_{s-1})$ in compressed form; the secret key
retains the pairs $(A_i^{-1}, B_i^{-1})$. These $s-1$ pairs are the long-term
secret that the attacks of Section~\ref{sec:app} recover.

\paragraph{Signing and the role of the seed tree.}
Algorithm~\ref{alg:sign_meds} follows the template of
Section~\ref{sec:template}. A fresh $\delta$ is expanded into a root seed
$\rho$ and a salt $\alpha$; line~5 grows the \GGM\ tree of
Definition~\ref{def:ggm} from $\rho$, yielding the $t$ ephemeral leaf seeds
$\sigma_0,\ldots,\sigma_{t-1}$. Each $\sigma_i$ is expanded into an ephemeral
equivalence $(\tilde{A}_i, \tilde{B}_i)$, and round $i$ commits to the
resulting generator matrix
$\tilde{G}_i = \SF(\pimap{\tilde{A}_i}{\tilde{B}_i}(G_0))$ by hashing its
non-systematic part. Hashing all $t$ commitments together with the message
gives the digest $d$, parsed into the weight-$w$ challenge
$\mathbf{h} = (h_0,\ldots,h_{t-1})$.

For each hidden round ($h_i > 0$) the signer publishes the response pair
\begin{equation}
  \label{eq:meds-resp}
  (\mu_i, \nu_i) \;=\; \bigl(\tilde{A}_i A_{h_i}^{-1},\;
                             B_{h_i}^{-1} \tilde{B}_i\bigr),
\end{equation}
and for the revealed rounds the seeds are released compactly through the path
$p \leftarrow \SeedTreeToPath_t(\mathbf{h},\rho,\alpha)$ computed at line~16.
Line~16 is the target of every attack in Section~\ref{sec:app}.

\paragraph{Verification.}
Verification (Algorithm~\ref{alg:verify_meds}, Appendix~\ref{app:algs})
recomputes the challenge from $d$, runs $\PathToSeedTree_t$ to recover the
$t-w$ revealed seeds, rebuilds every $\hat{G}_i$---from $(\mu_i,\nu_i)$ and
$G_{h_i}$ when $h_i > 0$, from the recovered seed when $h_i = 0$---and accepts
iff the recomputed digest equals $d$. Note that for hidden rounds the verifier
never uses $\sigma_i$: the seed of a hidden round is simply absent from an
honest signature.

\paragraph{Secret-extraction opportunity.}
This last observation is what the attacks exploit. Fix a hidden round $i$ with
$h_i = j$. The signature already contains $(\mu_i,\nu_i)$
from~\eqref{eq:meds-resp}. If an attacker additionally obtains $\sigma_i$, it
expands it into $(\tilde{A}_i,\tilde{B}_i)$ and reads off
\begin{equation}
  \label{eq:meds-extract}
  A_j^{-1} \;=\; \tilde{A}_i^{-1} \mu_i,
  \qquad
  B_j^{-1} \;=\; \nu_i \tilde{B}_i^{-1},
\end{equation}
by two matrix inversions and two multiplications over $\Fq$. The seed tree is
the \emph{sole} mechanism preventing this pair of revelations from occurring
together.

\subsection{LESS-v2}
\label{sec:less}
% ============================================================

LESS (Linear Equivalence Signature Scheme)~\cite{LESS-spec} applies the
Fiat--Shamir transform to a $3$-pass sigma protocol whose security rests on the
Canonical Form Linear Equivalence problem. The long-term secret is a set of
$s-1$ monomial matrices $\pi_1,\ldots,\pi_{s-1} \in \Mon_n(q)$; round $i$ needs
an ephemeral monomial matrix $\mathbf{Q}_{e_i}$ derived from the leaf seed
$\eseed_i$.

The two structural differences from MEDS are worth stating, since the fault
attacks of~\cite{ZKFault,FaultToForge2025} turn on them. First, LESS-v2 uses an
\emph{incomplete} \GGM\ tree: when $t$ is not a power of two, leaves sit at two
different depths and the implementation carries index-tracking arrays
($\mathsf{npl}$, $\mathsf{ll}$, $\mathsf{off}$, $\mathsf{lsi}$) to locate them.
Second, the path is computed from an explicit auxiliary \emph{flag tree} of the
same shape: $\LabelLeaves$ writes
$\calF(\mathrm{leaf}_i) = \mathbf{1}[i \in \calH]$ and $\ComputeSeeds$
propagates $\calF(v) = \calF(\ell) \vee \calF(r)$ upwards. Both the index
arithmetic and the flag array are extra state, and hence extra fault surface,
that MEDS does not have.

For a hidden round $i$ the signer publishes the coset representative
$\CosetRep(\pi_{b[i]} \circ \tilde{\pi}^*_i)$ while concealing $\eseed_i$.
Obtaining both recovers $\pi_{b[i]}$ by the column-extraction argument of
Lemma~1 in~\cite{FaultToForge2025} --- structurally
identical to~\eqref{eq:meds-extract}, with a permutation composition in place
of a matrix product.

\subsection{CROSS}
\label{sec:cross}
% ============================================================

CROSS~\cite{CROSSspec} is based on the Restricted Syndrome Decoding Problem
(R-SDP)~\cite{BaldiBPSWW24} and applies Fiat--Shamir to a $5$-pass protocol.
Its second challenge $\mathsf{chall}_2 \in \mathcal{B}(t,w)$ is a
\emph{binary} fixed-weight vector, so the hidden and revealed sets
$\calH = \{i : \mathsf{chall}_2[i] = 1\}$ and
$\calR = \{i : \mathsf{chall}_2[i] = 0\}$ have exactly the shape they have in
MEDS. Each leaf seed expands into a pair
$(\mathbf{e}'_i, \mathbf{u}'_i)$, from which the signer derives
$\mathbf{v}_i = \mathbf{e} \star (\mathbf{e}'_i)^{-1}$, where $\mathbf{e}$ is
the long-term R-SDP solution. A hidden round publishes $\mathbf{v}_i$; an
attacker holding $\mathbf{v}_i$ and $\eseed_i$ recovers
$\mathbf{e} = \mathbf{v}_i \star \mathbf{e}'_i$ directly, which is how
ZKFault~\cite{ZKFault} obtains full key recovery from a single fault.

CROSS additionally authenticates the $w$ commitments $\mathsf{cmt}_0[i]$ that
the verifier cannot recompute using a Merkle tree of size $O(w \log t)$. This
is a commitment-authenticity mechanism and is orthogonal to seed hiding; we
return to it in Proposition~\ref{prop:cross-gzkst}.

\subsection{The MPCitH and VOLEitH families}
\label{sec:mpcith}
% ============================================================

MPC-in-the-Head schemes use the tree in a superficially different but
structurally identical way. For each of $\tau$ repetitions, $N$ virtual party
shares are generated and the challenge selects one hidden party index
$i^*_e$; the signer publishes the \emph{co-path} of sibling nodes from
$\mathrm{leaf}_{i^*_e}$ to the root, which lets the verifier recompute the
other $N-1$ shares. Classic MPCitH schemes (Mirath, RYDE) use a forest of
$\tau$ trees; VOLEitH schemes (FAEST, SDitH~v2) use a single tree with
$\tau N$ leaves~\cite{OneTree}. The all-but-one vector commitment is the
counterpart of the flag tree, with $|\calH| = 1$ per repetition. We include
this family in the abstraction of Section~\ref{sec:abstract} but do not attack
it experimentally.
